# Chess Masti AI — notes for future Claude

Orientation for anyone (human or agent) picking up this codebase cold. Terse and load-bearing on purpose. For the fuller audit picture, see [AUDIT_NOTES.md](AUDIT_NOTES.md).

## What this is

Next.js 15 app (`chess-coach-ai/`, deploys to Vercel as **chessmasti.com**). Two tightly coupled surfaces: the AI coaching model and the web UI that wraps it. Chess rules via `chess.js`, board via `react-chessboard`, analysis via `stockfish.js` (WASM, in-browser Web Worker). Mixed Pages Router (`src/pages/*.tsx`) + App Router (`src/app/api/*` for route handlers, `src/app/layout.tsx`).

## AI architecture (the one mental model that matters)

Every server-side LLM call funnels through [`callLLM()`](src/lib/llmProvider.ts) in [src/lib/llmProvider.ts:216](src/lib/llmProvider.ts#L216). Anthropic Claude (Sonnet 4 flagship / Haiku 4.5 fast) is primary, OpenAI (gpt-4o / gpt-4o-mini) is the fallback. Any 4xx/5xx/network error on Anthropic triggers an immediate retry on OpenAI so a single user request is never dropped.

Callers use a `tier` (`"flagship" | "fast"`) — never a model name. Keep it that way.

Callsites (as of 2026-05-30):

- [src/app/api/enhanced-analysis/route.ts](src/app/api/enhanced-analysis/route.ts) — main deep analysis (`flagship`). ~2031 lines; do not refactor lightly. Embeds the Mastermind validator pipeline (`runValidationPipeline`) behind the `MASTERMIND_VALIDATORS_ENABLED` env flag.
- [src/app/api/chat/route.ts](src/app/api/chat/route.ts) — follow-up chat (`fast` → Haiku 4.5). Uses a server-cached context keyed by `contextId` from the prior analysis call. Since 2026-09-25 it has its own prompt, [src/lib/prompts/followUpPrompt.ts](src/lib/prompts/followUpPrompt.ts) (the idea behind the move and what actually happens, the line drawn by the app, a "Lesson:" with the pattern's name and the check to run next time, an optional "Your turn:" question; a 100-word budget, 140 for a walkthrough; `[CONTINUATION:n:c]` / `[PLAYED:n:c]` line tokens; `COACH_FOLLOWUP_PROMPT=legacy` restores the turn-1 prompt), grounds on the move the question names ([src/lib/coach/questionAnchor.ts](src/lib/coach/questionAnchor.ts), returned to the client as `anchor` so the board moves there) and sends a context cut to that move ([src/lib/coach/followUpContext.ts](src/lib/coach/followUpContext.ts)) instead of the whole `buildCompactGameContext()` summary. Output cap 600 tokens, history trimmed to four exchanges. See [MASTERMIND_CONTEXT/ANALYSIS_CONVERSATION_REWORK.md](MASTERMIND_CONTEXT/ANALYSIS_CONVERSATION_REWORK.md).
- [src/app/api/classify-intent/route.ts](src/app/api/classify-intent/route.ts) — exists but not currently wired into AnalysisImpl.
- [src/app/api/health/llm/route.ts](src/app/api/health/llm/route.ts) — 1-token probe, both providers.
- [src/lib/concept/conceptLLMTagger.ts](src/lib/concept/conceptLLMTagger.ts) — server-side concept classification.
- [src/lib/mastermind/categorization/categoryClassifier.ts](src/lib/mastermind/categorization/categoryClassifier.ts) — Haiku-tier intent classifier that picks the per-category timeout + retry budget for the validator pipeline.

**One board, one conversation.** Since 2026-09-25 `/analysis` is laid out like a chat assistant with a board beside it, and the rule for anything added to it is that it must not be a box or a moving part. Left column: the board, the evaluation arc as a scrubber (`EvalSparkline`, no card), and the strip under the board ([src/components/preview-analysis/MoveAnalysisCard.tsx](src/components/preview-analysis/MoveAnalysisCard.tsx)): one block of fixed height whose first row is the step buttons, the move with its verdict and evals, an "Ask Masti" and the board menu (flip, reset, the arrow overlays with Maia's Elo, copy link; the old chip row and navigator are gone), and whose next rows are the move's analysis. The exploring state ("Exploring 8.Qxc1 Rb8 · Back to move 7") and the coach's jump ("Showing 8. Nc7+, the move you asked about · Back") replace the move label in that first row at the same height; they used to be banners above the board, which resized it. Right column: a one-row header (Masti, his attitude, and the views Coach / Moves / Masters / Lines as words, `ViewSwitch`; there is no tab strip) over the transcript. Coach messages are prose beside Masti's face, user messages a soft bubble; there is no panel chrome, no BorderBeam, no entrance animation, and nothing pinned above the messages: the side question and the side line are part of the greeting (`PlayerSideAsk` / `PlayerSideChip`, inline), the book-exit note is the greeting's second paragraph (`BookExitCard variant="plain"`), and `ContextualPuzzleRecommendations` no longer mounts on `/analysis`. Below `lg` the panel is a screen tall (`calc(100dvh - 150px)`), so scrolling the board away leaves the conversation filling the phone; a tap on a line's Play scrolls the board back into view (`revealBoard`). Keep it that way: no new card above the transcript, nothing above the board, and nothing under it that changes height with the cursor.

**The coach panel draws lines, the model does not write them.** Every engine line the coach cites — under a key moment on turn 1, in the strip under the board, or a `[CONTINUATION:n:c]` / `[PLAYED:n:c]` token on its own line in a follow-up — is rendered by [src/components/preview-analysis/ProofLine.tsx](src/components/preview-analysis/ProofLine.tsx) from the client's own Stockfish data ([coachLines.ts](src/components/preview-analysis/coachLines.ts)): one quiet row of moves (clickable, scrolls sideways, never wraps), a Play control that steps the main board through it via the exploration preview, and under it one line of plain words for the move on the board (the first move's fact at rest, the current move's while it plays; [src/lib/coach/lineCaptions.ts](src/lib/coach/lineCaptions.ts) over `lineStory.ts`) with the material ledger at its right. No chips, no eval badge, no box. There is no Maia line on the client (the old "Maia line" box was the Stockfish PV twice). Key moments are passages of the coach's message separated by rules (`DarkInsightStack` / `DarkInsightCard`, chrome-less): the move and verdict, the lede, Idea and Problem, the line, Solution and Outcome, then the closing takeaway as a "Lesson" note ([insightWhy.ts](src/components/preview-analysis/insightWhy.ts) does the cut); "What happened in the game" and "Practice …" are text links, and the `[THREATS]` / `[ROLES]` sections the verbalizer still emits are not rendered (the coach answers from the same data when asked). A follow-up paragraph opening with "Lesson:" or "Your turn:" renders as the same note (`CoachNote`, a coloured rule, not a box). **Every move gets analysis, not just the key moments:** the strip under the board follows the cursor and, from the engine data alone ([moveAnalysis.ts](src/components/preview-analysis/moveAnalysis.ts)), gives the move's verdict, evals, what it does, why it works or not, and the engine's preferred line, with an "Ask Masti" that sends the question about that move.

**The legacy client-side AI service path is gone.** `src/lib/enhancedOpenAIService.ts` (989 lines), `src/hooks/useEnhancedFenTracker.ts` (337 lines), and `src/components/EnhancedAnalysisPanel.tsx` (294 lines) were all deleted in commit ca75f92 on 2026-04-25 ("Phase 0 of the coach-prompt restoration"). There is now only one AI path: `callLLM()`. If you see references to those files in older notes, treat them as stale.

System prompt body: [src/lib/prompts/coachChatPrompt.ts](src/lib/prompts/coachChatPrompt.ts) exports `getCoachChatSystemPrompt({ personalityId, userRating, username, playerColorName, coachingPrefs, ... })` — a ~455-line typed builder that composes the base coach manifesto with per-personality (`coachPersonalities.ts`) and per-prefs (`renderCoachingPrefs`) overrides. **Prompt version at [src/lib/prompts/coachChatPrompt.ts:22](src/lib/prompts/coachChatPrompt.ts#L22) is `"3.0"` (bumped from the deleted `"2.0"` template). Per-`analysisType` branching (`game_review` / `opening_analysis` / `endgame_analysis` etc.) is gone in 3.0; classification happens in the route via `categoryClassifier`, not in the prompt.**

## Rules that bit us in the audit

1. **CI now gates PRs on tsc + vitest.** [.github/workflows/ci.yml](.github/workflows/ci.yml) runs `npm ci → npx tsc --noEmit → npm test` on every PR and on push to main / audit/\*. The Vitest suite is 36 files / 652 tests (predominantly Mastermind validators, categorization, prompt builders, and llmProvider). `next.config.ts` no longer suppresses type errors, and [.eslintrc.json](.eslintrc.json)'s `ignorePatterns` is selective (only `node_modules`, `.next`, `Chesskit`, etc.) so `next lint` is now real too. **Keep `npx tsc --noEmit` clean** — there are still 32 `as any` / `@ts-ignore` escapes scattered through `src/`, so the type checker is the last line of defense against a lot of brittle code paths.
2. **Two `next.config` files exist, and `next.config.js` is the live one.** Next resolves the `.js` first, so `next.config.ts` is inert (its own header says so, and neither its COEP/COOP headers nor its Sentry wrapper have ever run in production). Anything that must take effect (headers, rewrites, `outputFileTracingIncludes`) goes in the `.js`. Consolidating the two is its own change with a full test pass: it switches on site-wide `require-corp`, which broke `/scout` when PR #367 tried it.
3. **Never accept a client-supplied system prompt or `role: "system"` message.** There was a P0 prompt-injection hole on `/api/enhanced-analysis` and `/api/chat` — Phase 1.4 of the audit stripped it. The proper Phase 3 fix (auth + rate-limit + server-side prompt allowlist) lands with a regression test. See the `AUDIT-PHASE-1.4` comments in [src/lib/validation/schemas.ts](src/lib/validation/schemas.ts) and [src/app/api/enhanced-analysis/route.ts](src/app/api/enhanced-analysis/route.ts).
4. **`Chesskit/` is out of scope.** Vendored nested git repo, currently dirty, quarantined in `.claude/settings.json`. Do not read, edit, or clean it.
5. **Temporary dev-server bind.** `npm run dev` binds to `127.0.0.1` (audit hardening). Use `npm run dev:lan` for LAN access. The choice to keep this binding long-term is a Phase 5 decision.

## Auth model (post-school-WiFi migration, 2026-04-28)

**Auth and Firestore reads no longer hit Firebase from the browser.** This was forced by school-network filters that block `*.firebaseapp.com` and `firestore.googleapis.com`. Everything routes through chessmasti.com server-side. Mental model:

- **Sessions**: signed JWT in an httpOnly cookie (`cm_session`). Sign-key in `SESSION_SECRET`. See [src/lib/auth/session.ts](src/lib/auth/session.ts).
- **Email/password auth**: bcrypt-hashed `passwordHash` field on the user doc. Endpoints under [src/app/api/auth/](src/app/api/auth/) — `signup`, `signin`, `signout`, `me`, `password`, `forgot-password`, `reset-password`.
- **Google OAuth**: server-routed via [src/app/api/auth/google/start](src/app/api/auth/google/start) + `callback`. The redirect_uri is chessmasti.com — never `*.firebaseapp.com`. Account-links by email so the existing 50 Firebase Auth users keep their UID and saved games when they sign in via Google for the first time.
- **Firestore reads**: server-side via Firebase Admin SDK ([src/lib/server/firebaseAdmin.ts](src/lib/server/firebaseAdmin.ts)). Browser calls `/api/users/me`, `/api/games`, etc. — never `firestore.googleapis.com` directly.
- **Personalization**: `users/{uid}` doc carries `coachTone`, `playingStyle`, `studyGoals`, `favoriteOpenings`, `boardTheme`, `pieceSet`, etc. The 4-tab ProfileDialog edits them. [/api/enhanced-analysis](src/app/api/enhanced-analysis/route.ts) reads the session cookie and threads prefs into `getCoachChatSystemPrompt`.
- **Intern mode (CMIP)**: at sign-in (Google OAuth + email/password), the auth callbacks check the email against the Supabase `intern_allowlist` table via [src/lib/intern/allowlist.ts](src/lib/intern/allowlist.ts) and stamp `isIntern: boolean` into the `cm_session` JWT claim. Flipping the allowlist takes effect on next sign-in. The browser reads `isIntern` from `/api/auth/me` via [useAuth](src/contexts/AuthContext.tsx) / [useViewer](src/hooks/useViewer.ts); intern-only UI (header EmployeePill, InternalNavLinks, InternalHomeCard, `/intern` dashboard, blue theme swap) is gated on this flag. See [MASTERMIND_CONTEXT/PR_CMIP_1_PLAN.md](MASTERMIND_CONTEXT/PR_CMIP_1_PLAN.md) for the broader plan.

**Things still using Firebase from the browser** (intentionally, since their domain isn't `firebaseapp.com`-blocked):

- `firebase/app` + `firebase/analytics` in [src/lib/firebase.ts](src/lib/firebase.ts).

**Stubbed but not deleted** (compile-only — TODO is to proxy through API):

- [src/lib/visitorTracker.ts](src/lib/visitorTracker.ts) — all reads return empty, writes are no-ops. /site-stats page renders blank until a `/api/visits` proxy lands.
- [src/lib/auth/getAuthHeader.ts](src/lib/auth/getAuthHeader.ts) — returns `{}` (cookies travel automatically; no Bearer header needed).

## Masti the Monkey (the mascot)

Masti is the Chess Masti mascot, used the way Duolingo uses Duo: he reacts to what the user does, fills loading and empty states, celebrates wins and softens losses. One rule above all: **he never sits over a board that is in play and never changes chess logic.** He only ever _reads_ state (a classification, a status, a result) through the pure reducers in [src/components/masti/mood.ts](src/components/masti/mood.ts).

- **Assets** live in the versioned, immutable-cached `public/masti/v5/` (twelve moods: the six the reducers produce, `wave`, `excited`, `idea`, `nervous`, `defeated`, `thinking`, plus `shocked` (a blunder with no side known, an opponent's brilliancy), `panic` (the third puzzle miss), `pointing` (a hint, an opponent's blunder, Commentator at rest), `smug` and `laughing` (Rival and Buddy at rest) and `banana` (a rating gain in the session recap); stills at 640 as WebP + PNG, 1122 as WebP only, and 320 `-sm` as WebP + PNG for avatars). v5 is the "Masti static pose pack, final logo" (the CM logo on the hoodie) and has **no animations**: `MASTI_LOOP_MS` is empty, `mastiAnimSrc` returns null and every figure rests on its still. The pack's own manifest lists animated `masti-final-logo-masti-v4-*` GIFs for six moods that were not in the zip; `v6` in `scripts/masti/lib/packs.mjs` already names them (the six animated states plus the six extra v2 poses, built from one directory holding both sets): when they arrive, run `node scripts/masti/build-assets.mjs --src <dir> --version v6`, bump `MASTI_VERSION`, fill `MASTI_LOOP_MS` from the built manifest, flip the hero e2e back to the burst, and rebuild the reels kit with the same version (v4 shows the shape: animated WebP at 480 and 240 wide, keyed to transparency from opaque GIF frames). Build with `node scripts/masti/build-assets.mjs --src <unzipped pack> --version v5`; never hand-edit the directory. A new pack is a new version directory plus a bump of `MASTI_VERSION` in [src/components/masti/manifest.ts](src/components/masti/manifest.ts); `manifest.test.ts` fails when the TypeScript manifest and the built JSON drift. `public/masti/v4/` stays for the reels kit, which is built from animations.
- **Components** in [src/components/masti/](src/components/masti/): `Masti` (the figure: still on the server and first paint, animation after mount for `loops` loops, then the still again; never under reduced motion, in a hidden tab, or off screen), `MastiAvatar` (a round face crop for chat headers and verdict pills, stills by default), `MastiSays` (speech bubble), `useStickyMood` (holds a mood for one loop so a 650 ms flash still plays). The `thinking` figure stands without a bubble of its own on the surfaces that use it (the v4 art carried a "give me a minute" bubble, the v5 chin-stroke does not).
- **Where he is**: home hero, the analysis coach header and every coach bubble, the puzzle coach panel, verdict pill, streak badge and recap, learn / course / trainer summaries, onboarding tour and nudge, the error boundary and the not-found page (`src/app/not-found.tsx`; the App Router serves every 404 in this mixed app, a `pages/404.tsx` never renders). Each surface computes a mood from its existing state with `puzzleMood` / `analysisMood` / `trendMood` / `scoreMood` and passes it down; do not add a new source of chess truth to do so.
- **He is the coach.** The analysis and puzzle panels are headed "Masti", not "AI Coach" or "Puzzle Coach", and the seven coach personalities in [src/config/coachPersonalities.ts](src/config/coachPersonalities.ts) are his attitudes (Grandmaster, Coach, Blitz, Professor, Buddy, Rival, Commentator Masti). Their ids are stable; each carries a `mood` that the attitude picker and the coach header wear at rest, so the Mastis look different. The system prompts identify as Masti (`coachChatPrompt.ts`, `puzzleChatPrompt.ts`, `puzzleHintPrompts.ts`); renaming an attitude means refreshing the per-personality prompt snapshots.
- **Rules that hold**: keep him out of the under-board strips on the viewport-locked `/analysis` and `/puzzles` layouts (every pixel there is board); `MastiAvatar` never animates below 32px and every figure under ~140px draws from the 320px still, so keep long transcripts and tiny glyphs to stills; any Masti copy that is a sign-in ask spreads `SIGN_IN_PROPS` (partner preview); keep landing copy clear of the `audiencePositioning.test.tsx` phrase list.
- **Reels and carousels**: the Instagram pipeline lives on the Mac, not here. [assets/masti/reels-kit/](assets/masti/reels-kit/) is the drop-in kit (deterministic sprite sheets, overlay CSS/JS, stills, demos, README with placement and the frame-zero rule), rebuilt by `scripts/masti/build-reels-kit.mjs`. OG share images (`src/app/api/og/*`, `src/app/og/*`) carry a still too.

## Opening courses (`src/data/courses/*.json`)

Generated, never hand-edited: `node scripts/openings/build-courses.mjs` from `src/data/master-tree.json` (the corpus, committed) + `src/data/eval-index.json` (Lichess CC0 evals, **gitignored**, streamed from the ~30 GB dump — see the `.gitignore` comment) + `src/data/eval-gaps.json` (our own Stockfish, **committed**). The model is in [scripts/openings/lib/course.mjs](scripts/openings/lib/course.mjs): their moves come from the corpus, ours from the engine. The three SYSTEM courses (`w-london`, `w-b3`, `w-tromp`) play a fixed setup with an engine veto — and **the veto needs a score**. The dump keeps five PVs, a setup move that hangs a piece is in none of them, and "unrated" used to pass as "fine": the 1.b3 course shipped 5.Be2?? with its knight en prise, labelled "engine-checked", until a learner reported it (2026-09-09). Guard C-4 now fails the build on any unscored setup move. Score them first, then build:

```
node scripts/openings/build-eval-gaps.mjs --only w-b3,w-london,w-tromp   # local Stockfish, ~1.5 h, resumable
node scripts/openings/build-courses.mjs --only w-b3,w-london,w-tromp     # leaves the other 40 untouched
```

Without the eval index only `--only` builds are possible. [src/lib/courses/__tests__/artifacts.test.ts](src/lib/courses/__tests__/artifacts.test.ts) asserts the invariants on the shipped JSON itself, so a stale artifact fails CI even when the builder is right.

## Tests & CI

**Vitest is wired and enforced by CI as of 2026-05-28.** `npm test` runs 383 files / 4924 tests (~4.5 min; the count in this line has been wrong before, so re-run before quoting it). [.github/workflows/ci.yml](.github/workflows/ci.yml) is `typecheck-and-test` (`tsc --noEmit` + vitest, the intended merge gate) running in parallel with `build-and-e2e`, itself a matrix of one leg per Playwright project (validator gate and contract smoke in the desktop leg only, then a production build and that project's suite). Playwright IS wired now — [playwright.config.ts](playwright.config.ts), `tests/e2e/local` against a local `next start` and `tests/e2e/prod` read-only against production.

Coverage is uneven on purpose: Mastermind validators, the category classifier, `getCoachChatSystemPrompt` (snapshotted per personality), and `llmProvider` fallback have deep tests; insight parsing, Firestore CRUD, the opening-explorer 3-tier fallback, the Maia integration, and SSE stream consumption have **none**. If you're touching one of the uncovered areas, write the test alongside the change — `chessmasti.com` is now small enough that "the next PR" is also the regression you'll have to debug.

The 30+ `test-*.js` files at the repo root are pre-vitest ad-hoc scripts. They aren't wired to `npm test` and don't run in CI. Treat them as dead code unless someone explicitly references one.

**Layout stability (CLS) is measured, not eyeballed.** [tests/e2e/local/layout-stability.spec.ts](tests/e2e/local/layout-stability.spec.ts) holds a per-route CLS budget on the five surfaces that had a real shift, and it only works because it throttles the browser first (`throttleLikeAPhone` in [tests/e2e/helpers.ts](tests/e2e/helpers.ts); it runs in the `local-mobile-light` leg only) — unthrottled, a `next start` paints the finished page before anything can be seen to move and every one of these bugs reports 0.0000. For attribution rather than a pass/fail, [scripts/perf/cls-probe.mjs](scripts/perf/cls-probe.mjs) drives a real Chromium at any base URL (production included) and prints which DOM node moved, when, and by how much.

The family of bug it guards against: **render something, find out what you should have rendered, then render that instead at a different size.** A `dynamic(ssr:false)` with no `loading` (the board is zero pixels tall until its chunk lands), a card gated on state that an effect always fills in, a placeholder whose height or width disagrees with what replaces it, a view rendered before the auth check answers. Reserve the final box from the first frame, and give each branch of a swap its own `key` so React mounts fresh instead of patching nodes in place — a reused node that lands somewhere else IS the layout shift.

One known, deliberate hole: [Lc0DownloadBanner](src/components/Lc0DownloadBanner.tsx) drops ~220px into the top of every non-self-chromed route when `/api/maia-status` reports Maia unhealthy, which is 0.26 of CLS. Production never pays it because Maia is live; CI and a bare checkout have no `MAIA_API_URL` and always do, which is why the specs call `stubMaiaHealthy`. If that banner is ever meant to be seen in anger it has to come in out of flow.

The synthetic-tester / eval harness lives in [scripts/synthetic-tester/](scripts/synthetic-tester/) with the Agent A baseline frozen at [audit/findings/agent-a-eval/](audit/findings/agent-a-eval/) (5 fixtures, 20% hallucination rate on Haiku 4.5). It does not run in CI; run it manually before shipping prompt changes.
