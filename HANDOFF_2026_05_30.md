## The big architectural changes — why they matter

### 1. Coach prompt cache split (PRs #70 + #77)

Before:

```ts
// coachChatPrompt.ts
return `${body}${userContext}`;

// route.ts
callLLM({ system: claudeSystemPrompt, cacheSystem: true });
```

After:

```ts
// coachChatPrompt.ts now also exports getCoachChatSystemPromptParts
return { stable: body, perUser: userContext };

// route.ts
callLLM({
  system: parts.stable,       // cached
  systemSuffix: parts.perUser, // uncached
  cacheSystem: true,
});
```

`llmProvider.ts` learned a new `systemSuffix?` field. When set + `cacheSystem: true`, Anthropic gets **two** system content blocks; only the first carries `cache_control: { type: "ephemeral" }`. Two users sharing a `personalityId` now hit the cache regardless of username/rating differences. OpenAI gets the concatenation (no cache concept on that side).

`storeAnalysisContext` persists the joined string + both halves; `/api/chat` reads the halves when present, falls back to the joined string for legacy entries.

### 2. PII fix + Sentry wiring (PRs #67 + #71)

Two separate issues:
- **Replays**: `maskAllText: false` + `replaysOnErrorSampleRate: 1.0` was capturing every keystroke during errors. Flipped to `maskAllText: true, maskAllInputs: true, sendDefaultPii: false`. Chess board pieces are PNG/SVG so `blockAllMedia` stays false (debugging continuity preserved).
- **Server-side observability**: 30 catch blocks → 0 Sentry calls. The audit didn't suggest wrapping ALL of them — most are graceful degradations (puzzle recs miss, validation warnings, prefs read failure). Identified the 12 truly-fatal sites (return 5xx to the client). Each handler closure now has a `reportFatal(err, phase, extra)` helper that filters `AbortError` and stamps `{route, requestId, phase}`.

### 3. Coach transcript persistence (PR #76 + #81)

The persistence story end-to-end:

- `Game` type gained `coachTranscript?: SavedCoachMessage[]`. `SavedCoachMessage` is intentionally slim (`role`, `content`, optional `ply` + `ts`) — runtime `CoachMessage` has `puzzlePack` / `drillState` / `insight` metadata that's re-derivable from `content`, so we don't persist it.
- `useGameDatabase` gained `setGameTranscript` which mirrors `setGameEval`: write IndexedDB first, then best-effort PATCH cloud via `updateCloudGameTranscript`. Failures swallow.
- `AnalysisImpl` runs a debounced `useEffect` that calls `setGameTranscript(savedGameId, slim(messages))` ~1s after the latest message change. Only fires when the user has explicitly saved the game (so anonymous chats never write to storage). `SEED_MESSAGES` (the Kasparov-Topalov greeting) is filtered out so it doesn't overwrite real conversations.
- Hydration: when `?gameId=N` is in the URL, `gameFromUrl` resolves; `AnalysisImpl` loads the PGN via `loadNewGame`, marks `saveState: "saved"`, and replaces `messages` with the persisted transcript.
- `/profile` lists saved games as tiles; clicking Open routes to `/analysis?gameId=N` which triggers the hydration above.

### 4. User rating threading (PRs #64 + #79)

Client (PR #64): `AnalysisImpl` reads `profile?.selfReportedRating` from `useViewer()` and passes it to `<CoachPanel userRating={…} />` instead of the constant 1500. `useViewer` extended to expose `profile` alongside `user`.

Server (PR #79): if any caller forgets to send `userRating`, the Firestore profile read (which already runs for `coachingPrefs`) now also captures `selfReportedRating`. `userRating = userRatingFromBody ?? profileRating`. All downstream code (skill calibration, buildGameContext, prompt composition, puzzle recommendations) sees the resolved value because they reference the destructured `userRating` which is now shadowed.

### 5. Markdown renderer restoration (PR #68)

The original symptom. `AnalysisImpl`'s `renderInline()` handled `**bold**` and SAN move references (clickable). Everything else (links, lists, code, headings, italics, blockquotes, tables) dropped to literal characters.

Restored by mirroring the legacy `AICoachChat` pattern:
- New `processChildren(node)` recursively walks React children, applying `renderInline` to string leaves.
- New `markdownComponents` map keyed by element type (`a`, `p`, `ul`, `ol`, `li`, `blockquote`, `h1-h4`, `em`, `code`, `hr`) — each forwards children through `processChildren` so move refs still tokenize inside markdown blocks.
- New `renderMarkdownProse(text)` wraps text in `<ReactMarkdown remarkPlugins={[remarkGfm]} components={markdownComponents}>`.
- Three call sites switched from `renderInline` to `renderMarkdownProse`: the no-INSIGHT fallback, and the prefix/suffix prose around the insight carousel.

**Critical detail**: `<strong>` is NOT in the components map. `renderInline` consumes `**foo**` syntax before remark-gfm sees it; an override would double-bold. The `a` component validates `href` against `http`/`https` — `javascript:` and `data:` URLs render as plain text instead of becoming live links.

## Common pitfalls

- **Replace_all on indented patterns**: `Edit` with `replace_all: true` only matches the EXACT pattern including indentation. Multi-site refactors with different indents need either separate edits or careful pattern selection. Today I had to redo this in PR #70 for the 6 callLLM sites.
- **Rebase conflicts on stacked PRs touching the same file**: today's PR #82 and PR #83 both modified the same LLM-result section of `enhanced-analysis/route.ts`. Both correct, both compatible — but git couldn't auto-merge. Rebased and accepted both halves.
- **Test files importing from `.tsx`**: vitest doesn't have `@vitejs/plugin-react` installed. Importing from a `.tsx` file that contains JSX makes vitest's transformer choke. Workaround: extract the testable code into a `.ts` sibling and re-export from the `.tsx` (pattern used for `AICoachInsights.parser.ts`).
- **The `Chesskit/` submodule**: shows as modified in `git status` constantly. Never include it in commits. CLAUDE.md and the engineering skill both call this out.
- **`useViewer` was originally intern-mode-only**: PR #64 extended it to expose `profile`. Don't accidentally trim that exposure in future refactors of the hook — `AnalysisImpl` reads `profile.selfReportedRating` from it.
- **The audit was written against an older revision in places**: when an audit finding says "X is broken," grep first.
- **`MASTERMIND_VALIDATORS_ENABLED` defaults FALSE in production**: most of the Mastermind validator pipeline code only runs in preview / explicit-opt-in environments. When wiring observability for "what the pipeline emits," remember production responses don't include pipeline data by default.
