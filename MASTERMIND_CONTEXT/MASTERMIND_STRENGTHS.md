# MASTERMIND_STRENGTHS.md

## SUMMARY

Where Chess Masti AI measurably outperforms competitors today, grounded in shipped code rather than aspiration. Seven strengths, each cited to the file that implements it. The headline differentiator is the engine-grounded coaching pipeline: Stockfish (or a structured engine output) is the source of chess truth, the LLM translates, and a chess.js-backed validator post-processes every claim before it reaches the user. On top of that sit five reinforcing systems: a ~200K-puzzle Neo4j graph with concept-first retrieval and a 49-dim handcrafted FEN-feature rerank for structural similarity; a two-tier Anthropic Sonnet/Haiku provider with prompt caching and OpenAI fallback; the Twin Bot opponent simulator (book replay → ELO-clamped engine play); a fully wired opponent-scouting pipeline with a football-card share asset; the live 5-category structured coaching prompt; and a Maia-2 (NeurIPS 2024) human-likeness service hosted on Hugging Face Spaces with a Vercel cron keep-alive. Each section below names the strength, cites the file(s), and explains why competitors don't match it. The Caveats section at the end documents where each strength is partial — including the legacy `enhancedOpenAIService.ts` parallel client-side path that bypasses the validator, and the FEN cosine 49-vs-50 label drift.

## 1. ~200K-puzzle Neo4j graph with concept-first retrieval and 49-dim FEN cosine rerank

The puzzle layer is a three-stage pipeline that no surveyed competitor matches end-to-end. Stage 1 hard-filters candidates from a Neo4j (Aura) graph of approximately 200,000 Lichess puzzles via a deterministic concept classifier on the anchor position; cross-concept candidates are excluded, not down-weighted ([conceptRetrieval.ts:1-21](../src/lib/concept/conceptRetrieval.ts#L1-L21), [puzzleRepository.ts:7-15](../src/lib/puzzleRepository.ts#L7-L15)). Stage 2 soft-reranks the survivors with the closed-form weighting `0.5·concept_confidence + 0.35·structural_similarity + 0.15·rating_proximity` ([conceptRetrieval.ts:37-48](../src/lib/concept/conceptRetrieval.ts#L37-L48)), where the structural signal is a handcrafted 49-dimensional FEN feature vector — material, pawn structure per file, pawn weaknesses, king safety, centralization, phase, castling/special — combined via cosine similarity ([fenSimilarity.ts:14-80](../src/lib/fenSimilarity.ts#L14-L80)). Stage 3 picks the final `limit` by max-marginal relevance with `MMR_LAMBDA = 0.3` so the user sees the same concept in varied surface forms (interleaving for retention; [conceptRetrieval.ts:43,349](../src/lib/concept/conceptRetrieval.ts#L43-L349)). Lichess and Chess.com surface puzzles by theme tag only; ChessPuzzle.net's pattern taxonomy is finer but not paired with structural rerank; OpeningTree has no puzzle layer. Chess Masti is the only product in the gap analysis combining graph traversal, structural cosine rerank, and MMR diversity in one pipeline.

## 2. Hallucination validator: chess.js cross-check on every LLM claim

Every server-side LLM coaching response is post-processed against the actual board state before it reaches the user. The validator parses the response with regex-tuned patterns for piece-on-square claims (`"knight on e5"`, `"the bishop at c4"`), move suggestions in SAN/UCI, and square references; it then verifies each claim against a `chess.js` board constructed from the position's FEN ([aiResponseValidator.ts:38-86](../src/lib/aiResponseValidator.ts#L38-L86), [aiResponseValidator.ts:92-124](../src/lib/aiResponseValidator.ts#L92-L124)). Errors and warnings are scored (`error * 0.2 + warning * 0.05` deduction), and any error appends a footnote that flags the response as potentially inaccurate ([aiResponseValidator.ts:65-78](../src/lib/aiResponseValidator.ts#L65-L78)). The validator is invoked in production by the two server-side coaching routes that call `callLLM()`: deep analysis at [enhanced-analysis/route.ts:1272,1388](../src/app/api/enhanced-analysis/route.ts#L1272-L1388) and follow-up chat at [chat/route.ts:115](../src/app/api/chat/route.ts#L115). The Quality Improvement Plan ([Chess_Masti_AI_Quality_Improvement_Plan.docx](../Chess_Masti_AI_Quality_Improvement_Plan.docx)) names this exact validation requirement (Section 2 step 5) — Chess Masti has it, and the Feb 2026 gap analysis ([_sources/gap_analysis_roadmap_feb2026.md](_sources/gap_analysis_roadmap_feb2026.md)) does not list any competitor that ships an equivalent.

## 3. Two-tier Anthropic Sonnet/Haiku with prompt caching and OpenAI fallback

A single `callLLM()` entry point routes by `tier` rather than model name: `"flagship"` → Claude Sonnet 4 (`claude-sonnet-4-20250514`), `"fast"` → Claude Haiku 4.5 (`claude-haiku-4-5-20251001`) ([llmProvider.ts:83-92](../src/lib/llmProvider.ts#L83-L92)). When a caller sets `cacheSystem: true`, the system prompt is sent with an `ephemeral` cache marker so subsequent calls within ~5 minutes reuse the cached prompt as a much cheaper cache read ([llmProvider.ts:56-64](../src/lib/llmProvider.ts#L56-L64), [llmProvider.ts:106-113](../src/lib/llmProvider.ts#L106-L113)) — the system prompt at [chessPrinciples.ts:172](../src/lib/chessPrinciples.ts#L172) is large and reused, so cache hits are roughly 10× cheaper. Any 4xx, 5xx, or network error from Anthropic triggers an immediate retry against OpenAI (`gpt-4o` flagship, `gpt-4o-mini` fast) so a single user request is never dropped ([llmProvider.ts:99-101,131-135,193-211](../src/lib/llmProvider.ts#L99-L211)). The unified return shape carries `cacheCreationTokens`, `cacheReadTokens`, `elapsedMs`, and `primaryError`, so cost telemetry is observable per call. The Quality Improvement Plan calls out that no competitor ships a tiered model strategy with prompt caching plus a cross-provider fallback as a single user-invisible primitive.

## 4. Twin Bot — book-then-engine opponent simulator

The Twin Bot mirrors a specific opponent's actual play in two phases. The book phase walks the opponent's own opening tree (built by [scoutService.ts:16-22](../src/lib/scoutService.ts#L16-L22) from their public games), picking a child weighted by how often the opponent themselves played it; randomness is tunable from `0` (always the most-played reply) to `1` (proportional to frequency, with `0.35` as the default mix) ([twinBot.ts:50-70](../src/lib/twinBot.ts#L50-L70), [twinBot.ts:88-100](../src/lib/twinBot.ts#L88-L100)). Once the position falls out of book, the bot delegates to Stockfish with `UCI_LimitStrength` + `UCI_Elo` set to the opponent's phase-specific rating (opening/middle/endgame buckets), so the engine plays at level-appropriate strength rather than at full Stockfish ([twinBot.ts:1-22](../src/lib/twinBot.ts#L1-L22)). The output declares its source (`"book" | "engine" | "fallback"`) and, when in book, the share-of-games confidence at that node ([twinBot.ts:25-48](../src/lib/twinBot.ts#L25-L48)). The Feb 2026 gap analysis lists Noctie.ai as the only competitor with a humanlike opponent feature; Noctie does not pair the humanlike engine with the opponent's own repertoire data. Twin Bot is therefore a category of one in the surveyed landscape: a per-opponent rehearsal partner.

## 5. Opponent scouting pipeline + share card

Given a chess.com or lichess username, the scout pipeline ingests their public games and builds an opening tree with W/D/L per branch, capped at `maxDepth = 25`, with single-node FEN serialization that reuses one `Chess` instance across games for performance ([scoutService.ts:16-22](../src/lib/scoutService.ts#L16-L22), [scoutService.ts:36-80](../src/lib/scoutService.ts#L36-L80)). Aggregate analytics over the same dataset produce the player's ATK/DEF/TIME/MIND/OVR profile and a "stalker" score (consumed downstream as `ProfileSnapshot` and `StalkerScore` in [shareCard.ts:9-20](../src/lib/shareCard.ts#L9-L20)). The output renders to a 720×1024 SVG-built share card in football-sticker style — entirely inline, no external assets, exported as a transparent-free PNG via an offscreen canvas ([shareCard.ts:1-7,42-67](../src/lib/shareCard.ts#L1-L67)) — making the report virally shareable. The route surface lives at [api/scout/](../src/app/api/scout/). OpeningTree provides per-player tree visualization but no aggregate scouting profile and no share asset; Aimchess provides aggregate diagnostics but not against an arbitrary opponent. The combination — opponent tree + scouting profile + ready-to-share visual — is unique in the surveyed competitive set.

## 6. 5-category structured coaching prompt (Threats / Best Moves / Plans / Piece Roles / Concepts)

The Quality Improvement Plan ([Chess_Masti_AI_Quality_Improvement_Plan.docx](../Chess_Masti_AI_Quality_Improvement_Plan.docx) §3) names DecodeChess's five-category breakdown as the structure that makes professional-grade chess feedback feel complete: Threats, Best Moves, Plans, Piece Roles, Concepts. The Chess Masti coach prompt is built around this framework and explicitly tells the model to select which categories are most relevant to the position rather than fill all five every time ([coachChatPrompt.ts:170](../src/lib/prompts/coachChatPrompt.ts#L170)). The prompt is versioned (`PROMPT_VERSION = "3.0"` at [coachChatPrompt.ts:22](../src/lib/prompts/coachChatPrompt.ts#L22)) so before/after evaluation runs are comparable. The deep-analysis route imports it directly: `getCoachChatSystemPrompt`, `PROMPT_VERSION` at [enhanced-analysis/route.ts:14-17](../src/app/api/enhanced-analysis/route.ts#L14-L17). The prompt is also a pure function (same inputs → same output), which lets the response cache key off the structured input rather than the raw text. Among the surveyed competitors only DecodeChess matches the structure; DecodeChess is paid and English-only, while Chess Masti's structured layer is wired into the same conversational coach that also handles follow-up Q&A (a combination Sensei Chess approximates but without DecodeChess-grade structure).

## 7. Maia-2 (NeurIPS 2024) human-likeness via Hugging Face Spaces

Human-likeness predictions come from Maia-2 — the 2024 NeurIPS revision of the Maia model — running as a separate Python/FastAPI microservice on Hugging Face Spaces, because Vercel serverless cannot host PyTorch or LC0 ([api/maia-predict/route.ts:7-12](../src/app/api/maia-predict/route.ts#L7-L12)). The Vercel route at [api/maia-predict/route.ts:38-46](../src/app/api/maia-predict/route.ts#L38-L46) proxies POST `/predict` with `{fen, rating, opponent_rating}` and returns `{humanLikeMove, confidence, alternativeMoves, rating, model}`. Status is exposed via [api/maia-status/route.ts:25-46](../src/app/api/maia-status/route.ts#L25-L46), which checks the upstream `/health` endpoint and reports `model_loaded`. Because HF free-tier Spaces sleep after 48 hours of inactivity (warm-up cost 30–90 seconds), a Vercel cron pings the Space every 12 hours via [api/keep-maia-alive/route.ts:1-13,42-54](../src/app/api/keep-maia-alive/route.ts#L1-L54), authorized by `CRON_SECRET`, with a 110-second abort budget tuned to HF cold-start latency. The Feb 2026 gap analysis ([_sources/gap_analysis_roadmap_feb2026.md](_sources/gap_analysis_roadmap_feb2026.md) §3) identifies Noctie as the only competitor with a humanlike opponent; Noctie's model is proprietary and not the published Maia-2 lineage. Chess Masti is the only surveyed product wiring Maia-2 specifically into a coaching surface.

## Caveats — where each strength is partial

These do not reverse the strength claims above, but the Mastermind agent should know the seams.

- **5-category structured prompt — Phase 2 cache-key integration pending.** The doc comment at [coachChatPrompt.ts:10-12](../src/lib/prompts/coachChatPrompt.ts#L10-L12) was written when the module was new and says "Wiring into the route happens in Phase 2 — this module is built but not yet imported by any route handler." The route now imports it (verified at [enhanced-analysis/route.ts:14-17](../src/app/api/enhanced-analysis/route.ts#L14-L17)), so the baseline wiring is live. What remains for Phase 2 is folding `PROMPT_VERSION` into the response-cache key prefix so cross-deploy stale entries become unreachable ([coachChatPrompt.ts:18-20](../src/lib/prompts/coachChatPrompt.ts#L18-L20)). Until that ships, a deploy that changes the prompt body without bumping `PROMPT_VERSION` could serve cached output from the prior prompt.
- **FEN cosine: 49 dims, internally labeled `handcrafted-50d-v1`.** The file header comment in [fenSimilarity.ts:7](../src/lib/fenSimilarity.ts#L7) says "~50-dim feature vector" and the embedding-version constant at [conceptRetrieval.ts:48](../src/lib/concept/conceptRetrieval.ts#L48) is `"handcrafted-50d-v1"`. Counting the actual fields in the `FENFeatures` interface ([fenSimilarity.ts:14-80](../src/lib/fenSimilarity.ts#L14-L80)) gives 49: 5+5 material, 8+8 pawns-per-file, 8 pawn weaknesses, 4 king safety, 4 centralization, 3 phase (treating `isEndgame` as one bit), 4 special — total 49. The strength claim ("49-dim FEN cosine") is correct; the documentation drift is in the source's own header comment and version string. Flagged here, separate-PR fix.
- **Hallucination validator — legacy parallel path bypasses it.** The validator only fires when the LLM call goes through the server-side `callLLM()` (verified call sites: [enhanced-analysis/route.ts:1272,1388](../src/app/api/enhanced-analysis/route.ts#L1272-L1388), [chat/route.ts:115](../src/app/api/chat/route.ts#L115)). The legacy [enhancedOpenAIService.ts](../src/lib/enhancedOpenAIService.ts) (989 lines) is instantiated **client-side** in [useEnhancedFenTracker.ts:88](../src/hooks/useEnhancedFenTracker.ts#L88) and consumed by [EnhancedAnalysisPanel.tsx](../src/components/EnhancedAnalysisPanel.tsx); a `grep` of `validateAIResponse` shows zero call sites in that file. So any user surface that still routes through the legacy client-side service receives unvalidated output. Per CLAUDE.md and the audit notes, this path is parallel to (not replaced by) `callLLM()`. The Mastermind agent should prefer the server-side routes when correctness matters; if a coaching surface ever surfaces validator warnings as "trustworthy by default", that contract is only honored by the `callLLM()` paths. Removing the legacy path is a separate cleanup effort.
- **Two-tier Sonnet/Haiku — OpenAI fallback is coded but not operationally integrated.** The fallback retry logic in [llmProvider.ts:99-101,131-135,193-211](../src/lib/llmProvider.ts#L99-L211) is correct, but per the runtime-readiness table in [CLAUDE.md](../CLAUDE.md) the `OPENAI_API_KEY` is not currently configured for the deployed environment. So in the live single-provider mode, an Anthropic 5xx falls through to a user-facing error rather than to OpenAI. The strength claim — that the fallback path exists and is wired — is true; the operational guarantee is currently weaker. Adding the OPENAI key is an env-config step, not a code change.
- **Maia-2 — depends on `MAIA_API_URL` env var; 503s gracefully if unset.** [api/maia-predict/route.ts:25-35](../src/app/api/maia-predict/route.ts#L25-L35) returns HTTP 503 with `{fallback: true}` when the env var is missing; the strength claim assumes the deployed environment has the URL configured. Local dev without it will not produce Maia predictions; the agent should `GET /api/maia-status` to confirm reachability before promising humanlike-move output.
- **~200K Neo4j puzzle graph — exact count and ingest filter discrepancy.** Two ingest scripts exist: [scripts/build-puzzle-db.py](../scripts/build-puzzle-db.py) uses `MIN_NB_PLAYS = 50`, while [scripts/import-lichess-puzzles.mjs](../scripts/import-lichess-puzzles.mjs) defaults to `--min-plays 100`. Both share `MIN_POPULARITY = 60`. The ~200K count in [puzzleRepository.ts:7-15](../src/lib/puzzleRepository.ts#L7-L15) is approximate; live `count(p:Puzzle)` in Aura would resolve which ingest path produced the current corpus. For the strength claim the order of magnitude is correct; for filter-policy claims the doc should cite the script that actually ran most recently.
- **Twin Bot fallback path.** The `TwinBotMoveSource` enum includes `"fallback"` ([twinBot.ts:25](../src/lib/twinBot.ts#L25)) for the case where neither the book lookup nor the engine call returns a usable move (e.g., engine init failure mid-game). The fallback output's chess quality is not specified in the strength claim above; in practice it is whatever the caller's degraded path produces. Worth surfacing in the agent's tool result so a coaching turn can acknowledge "the rehearsal partner went off-script."
- **5-category prompt — feature deltas at the resolution point are not yet wired in (Stage 3 grounding).** Added 2026-05-08 after a Reddit-thread audit of the Take Take Take / Nova Chess move-explanation pipeline confirmed parity on Stockfish + feature extraction + LLM-as-translator (strengths 1, 2, 6 above), but a gap on the third stage: feature deltas computed at the variation's resolution point. Today [positionAnnotator.ts](../src/lib/positionAnnotator.ts) is invoked once per move on the resulting FEN at [enhanced-analysis/route.ts:558](../src/app/api/enhanced-analysis/route.ts#L558); we compute eval deltas (`cpBefore`/`cpAfter`) but not feature deltas. Tablebase is also entirely absent from the codebase. The LLM has to infer "what changed" from a static snapshot, which produces vaguer prose than competitor outputs that name specific structural changes ("creates a backward d6 pawn you can target"). Planned remediation lives at [FUTURE_IDEAS.md §1 Stage 3](../FUTURE_IDEAS.md) — `compute_feature_delta` + `find_resolution_point` + `fetch_lichess_tablebase` ship into the existing flagship `enhanced-analysis` flow first (mandatory call sites per MASTERMIND_TOOLS.md "Mandatory call sites" section), then become Mastermind-agent tools. Until that lands, claim 6 is true at the prompt-structure level (5 categories shipped) but understated at the grounding level (no per-move feature-change input to the LLM).

Updates to these caveats land in MASTERMIND_FAILURE_MODES.md (doc #6); this file lists them only insofar as they qualify a strength claim.
